# 実測

**測った値だけを置く。** 規則はここを引く。

なぜ分けてあるか — 数字は測り直せば変わる。規則の条文に埋めておくと、
測り直したときに何か所直せばよいか分からなくなる。実際、同じ数字が四か所に
散っていて、一か所だけ直して食い違った（事故-19（1-壊れ方.md））。

**書き方** — 測った日・何を測ったか・標本の数を必ず添える。
添えていない数字は使わない。

## 実測-15 RanobeDB の使っていなかった欄（2026-08-05 / 控え 30 系列）

```
bookwalker_id を持つ    30 / 30   100%   ← 語で検索せず系列頁へ直行できる
title ≠ title_orig      13 / 30    43%   ← title は英語。title_orig が日本語
child_series を持つ      5 / 30    17%   ← 派生と母体の関係（relation_type 付き）
```

端点の実態:

```
/series?q=      volumes.count・c_num_books・sim_score を持つ
/book/{id}      releases[] に isbn13・format(print/digital)・pages
/releases?q=<isbn>   **正確**。実在の ISBN で 1 件、架空の ISBN で 0 件
/books?isbn=<isbn>   **効かない**。架空の ISBN でも同じ 24 件を返す（使うな）
```

`releases[]` は `ja/print/20170210` と `ja/digital/20170310` を分けて持つ。
検め-4 が「月まで」に落としているずれは、ここを見れば正確に合わせられる。

`publication_status` は三値 — `ongoing 21 / completed 6 / unknown 3`。
**独立した `unknown` がある**ので、「ongoing は既定値」という旧説は疑わしい。
`c_end_date` は完結なら実日付、未完結なら `99999999` の二値できれい。

## 実測-20 索引が静かに欠ける（2026-08-05 / 264 か月を二度くだして比較）

ラノベの杜は、**HTTP 200 のまま中身の欠けた応答を返すことがある**。

```
正しい月ページ   80,000 〜 300,000 バイト
壊れた応答        754 バイト（まだ来ていない月の応答と同じもの）
```

一度目のくだしで 15 か月がこれに当たり、**索引から 4,709 件が静かに消えた**。
道具は「成功 264 / 失敗 0」と報告していた。

```
1 回目   86,286 件（15 か月が 0 件）
2 回目   90,995 件（取り直した）
```

**間欠的。** 同じ月が一度目は 0 件、取り直すと 654 件返る（2025/01 で実測）。

対処は二つ。

```
① 過ぎた月が 0 件になることは無い → 3 秒空けて二度取り直す
② それでも 0 件なら、前の分を残して報告する（上書きしない）
```

まだ来ていない月（2026/09 以降）は本当に 0 件なので、そこは区別する。

★ この形の壊れ方は **1-壊れ方.md 八章「測り方が間違っていた」** に属する —
「成功した」という報告が、成功していないことを隠していた。

## 実測-22 杜の索引は 12 月末の本の年を一つずらす（2026-08-05 / 四例）

```
                                杜の索引    RDB と手元    実際
六畳間の侵略者!?21               161229     151229       15年12月29日
最低ランクの冒険者…3             231228     221228       22年12月28日
最低ランクの冒険者…5             241228     231228       23年12月28日
陰キャの僕に罰ゲームで…5          231228     221228       22年12月28日
```

**四例とも 12 月 28〜29 日の発売。** 杜はそれを翌年 12 月の頁に置いている。
六畳間 21 は並びでも露わになる — 18(150131) 19(150601) 20(150901)
**21(161229)** 22(160430) と、21 巻が 24 巻より後に来る。

## 実測-40〜42 題名の書き方の割れ — 杜を引く道を三つ足した（2026-08-07）

新しい置き場で「杜が黙っている」が 52 件あった。全部**同じ一冊が
出しどころによって違う書き方をされている**だけだった。

```

実測-41  末尾に付いた叢書の標   手元「化物語（上） <物語>」  杜「化物語 (上)」
実測-42  括弧が在るか無いか     手元「終物語 下」           杜「終物語 (下)」
```

**どれも一件に絞れたときだけ答える。** 索引 90,995 件で重なりを測った:

```

                                        全部「(上)」と「<上>」のような同じ一冊

                                        多くは【新装版】や(初回限定特装版)で**本当に別の版**
実測-42  括弧そのものを落とす         →  新たに重なる組 5,280
                                        大半は杜が同じ一冊を括弧違いで二度載せたもの
```

★ **重なりが増えること自体は取り違えにならない。** 二行あればその道は黙るので、
  増えた分は「答えない」に変わるだけ。だから弱い道ほど**後ろに**置けばよい。

★ 落として良いものと駄目なものの線は **巻を見分けられるか**。
  `<物語>` は叢書名なので落として良い。`〈下〉` を落とすと巻を取り違える
  （壊れ方 1-9）。なので **中身に 上中下前後完・数字を含む括弧には触らない**。
  `<Infinite Dendrogram>` のように**頭に来る括弧**も題名そのものなので触らない。

★ 括弧を落としても「猫物語黒」と「猫物語白」は分かれたまま。
  **落とすのは括弧であって、中身ではない。**

### 足した道が一つも通らなかった — 門の書き方の誤り

三つ足したのに 3 件しか増えなかった。原因は入口の条件:

```python
k6 = _NO_BRACKET.sub("", _shape(k2 or k))
if k6 and k6 not in (k, k2, k3, k4, k5):   # ← これ
```

「手元の鍵が変わらなかったなら見ても無駄」という節約のつもりだったが、
**この道は索引の側も落として比べる**。手元「終物語 下」は元から括弧が無いので
`k6 == k` になり、杜の側の「終物語 (下)」を落とす前に道が閉じていた。

★ **両側を変えて比べる道に「手元が変わったか」の条件を付けてはいけない。**
  同じ誤りが、前からあった「読みを落として」にも入っていた。

## 実測-43 `(1)` は漫画の巻、裸の `1` は小説の巻（2026-08-07）

実測-42 の「括弧を落として」を入れた直後、その道が**小説とそのコミカライズを
同じ一冊にした**:

```
手元「嘆きの亡霊は引退したい… 1」（小説・GCノベルズ）
  → 電撃コミックスNEXT「嘆きの亡霊は引退したい… (1)」（漫画）
手元「一生働きたくない俺が…懐かれたら 6」（小説・オーバーラップ文庫）
  → ガルドコミックス「一生働きたくない俺が…懐かれたら (6)」（漫画）
```

ラノベの表記では **`(N)` が漫画版の巻、裸の `N` が小説の巻**という
書き分けが広く使われている。括弧を落とすとこの区別が消える。

**直し方** 中身が数字だけの括弧は外さない。`(黒)` `(下)` は外して良い。

```python
_NO_BRACKET = re.compile(r"\(([^()]*[^\d()][^()]*)\)")   # 中身に数字以外を要る
```

★ **重なりの数を数えるだけでは、この誤りは見えなかった。** 実測-42 で
  5,280 組が重なると測り、その中身を「杜が同じ一冊を二度載せたもの」と
  読んだ。**その中に小説と漫画の組が混ざっていた。**
  数えたあと**種類の違うものが混ざっていないか**を見る。

**被害** 台帳に 3 件（特典が漫画の巻に付いた）。検めの
「特典の頭が OPF の『』と食い違う」が全部捕まえた。
**足した道が誤りを生んでも、検めが受け止められる形になっていた。**
