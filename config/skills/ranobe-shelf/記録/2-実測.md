# 現行規則の検証方法

共有するのは、別の棚でも確かめるべき性質と検証手順。処理件数、実行日時、実パス、合否結果はGit対象外の `local-run.md` と作業データに残す。

## 仮の棚で確かめること

- 文庫の異なる同名本を別配置し、同文庫内の衝突は上書きせず止める。
- 著者・画師・日付・巻別・版別情報を保持し、文庫はフォルダで表す。
- 旧配置規則の計画、元ファイル欠落、情報落ち、計画後の台帳変更を拒否する。
- 移動後は台帳pathと実体が一致し、取消で戻せる。保留本は通常計画で引き戻されない。
- 未決を指定理由フォルダへ移動し、既存書誌と原bytesを保持する。指紋違い・衝突・移動失敗は成功扱いにしない。
- 候補表示だけでは台帳を変更しない。特典の候補から親巻ISBNや日付を自動転記しない。
- 状態階層と欠巻TXTを生成しない。

## 実行手順

スキルのディレクトリで `python scripts/test.py` を実行する。`python scripts/check.py` は試験も実行し、未使用コード、文書と命令の不一致、壊れたリンクなどを検査する。通常は後者で両方を確認できる。

本棚に適用するときは今回の移動元・先・台帳IDを控え、原bytesのSHA256、サイズ、更新時刻と台帳pathを照合する。同一ボリューム内ではfileIDも確認し、別ボリューム間の移動ではfileIDが変わるため、完全SHAとサイズ・更新時刻で保全を確認する。確認できた範囲と未実施の比較を実行記録で区別する。
