# ranobe-shelf

実際の巻と版を確認し、文庫別フォルダへ配置する。道具は材料の収集と、確定した記録・移動を行う。候補からの採否判断は中身を読んで行う。

## 媒体種別を先に確認し、小説の中で軽小説を判断する

まず当該実体を「小説・漫画・その他・未確認」に区別し、単書根拠を記録する。漫画化・映画小説化など同じ原作者の別媒体を別実体として扱う。漫画・その他は軽小説の連帯判定から外し、未確認なら媒体確認待ちにする。小説と確認できた実体に限り、軽小説かを直接または下記の連帯判定で判断する。省略できるのは、ユーザーがその本をライトノベルだと明示した場合、または種類の判別は不要だと明示した場合だけ。指定された本・範囲に限って例外を適用し、「このフォルダを整理して」という依頼やフォルダ名だけで判別不要とは解釈しない。

出版社・文庫の同版書誌、販売分類、実際の本文・構成を根拠にする。番外・特典は対応する原作シリーズ・巻と、その実体が小説なのか画集・漫画・設定資料なのかも確認する。母出版社、判型、挿絵の有無、ファイル名だけでは決めない。

- ライトノベルに当たる：根拠を記録し、対象文庫の範囲確認と整理へ進む。
- ライトノベルではない：根拠を記録して、その本の整理を中止する。追加の書誌補完、改名、変換、修復、入架は行わず、原本を保つ。直接判定は原位置を保持し、連帯判定は下記の専用保管規則に従う。判別済みの対象外を「処理失敗」として未決フォルダへ移さない。対象外資料の移動は別途ユーザーの指示がある場合だけ、その指定に従う。
- 判別できない：採用せず、足りない証拠と再開条件を記録して、種類の判別待ちとして理由別保管する。未判定を非ライトノベルと断定しない。

判断結果・根拠・対象の巻と版、または判別を省略したユーザーの明示指定を、本機の台帳・調査記録に残す。同じ巻・版の既存判断と根拠を確認できれば再利用できる。別版や新たな矛盾があれば見直すが、規則追加だけを理由に完了済みの棚全体を再処理しない。ユーザーによる判別免除も、対象文庫の範囲や原本保全など他の規則を解除するものではない。

## ユーザーの判定を最優先する

続行時・分類や移動の決定前に、作業データの `human-review.jsonl` があれば読む。同一実体のユーザー判定は、自動分類・連帯推定・過去の調査より優先する。正確性を再審査せず、ユーザー自身の変更・撤回だけを反映する。pathだけで別実体へ転用せず、保存されたdevice/fileID/size/mtime、移動後は必要に応じて完全SHA256で対応を確認する。

- `mode: classify` の `ln / non_ln / related` は、それぞれ「軽小説」「非軽小説」「漫画またはその他二次元関連資料」という確定したユーザー判断。`related` は漫画と断定せず独立した分類を保つ。後二者の分類結果は一般の連帯除外と混ぜず、既存の適切な理由別保管へ反映する。判断済みの同一実体を再び軽小説判別待ちへ戻さない。軽小説判断後も文庫範囲・巻版・完全性を確認する。
- `mode: shelf` の `recheck / ok` は「再確認が必要」「今回の復審で問題なし」。`recheck` は再確認キューへ入れ、非軽小説とは推定しない。`ok` を別の分類判断へ拡張しない。
- `mode: shelf` の `discard` はユーザーが指定した「抛弃卷」。再確認・以後の整理・再入架から除外し、原本を棚外保管へ移す。非軽小説・漫画の分類や連帯票へ読み替えない。巻台帳は同じ巻IDで現path・非採用・`判断.棚外`を追記し、通常計画が棚へ戻さないようにする。ユーザーが撤回した場合だけ元の棚位置と採用状態へ戻す。移動前後の完全SHA・実体識別、衝突なし、台帳追記の成功を確認して完了扱いとする。
- `scope: entity` の `veto_author / veto_publisher` は、ユーザーが明示選択した著者／出版社全体の否決。現在と今後の整理待ちに、保存された正規化済み完全名で適用して処理を中止する。連帯推定とは別のユーザー指定除外として記録し、L/N票には数えない。単書の同定済み著者・出版社を渡して照合し、原作者・画師など未分離の署名からの選択はユーザーが選んだ具体名を保持する。未知名、部分名、母出版社や別名への拡張はしない。既存棚の同主体全巻を撤去する指定ではなく、棚の撤去は単巻の`discard`による。`undo`で当該主体の否決を撤回する。同じユーザーによる後の単書判断があればその明示変更を優先する。
- JSONLは1行ずつ読み、`mode + book_id` ごとの最新イベントを採用する。`undo` はその判定を撤回する。読み込んだだけ・画面を開いただけでは判断を付けず、ユーザーが「次の本」を押した時に既定判断を記録する。件数は容器単位で、同じ作者・シリーズへの判断拡張はしない。
- 判定原文と対応する元実体・現在pathを追記記録に残す。ユーザー判断を有効な連帯票に加える場合も、小説媒体の確認と同巻・合本の重複排除は別途行い、`related` や復審フラグを小説票に数えない。

本機の画面・起動場所・読取補助コマンドは `記録/local-run.md` に記す。レビュー記録は作業資産として保全し、共有リポジトリに含めない。

## 著者・出版社による連帯判定

小説という単書の媒体確認が済み、軽小説かの直接判定が無い本に連帯判定を適用する。著者ごと・出版社ごとに「確認済み小説のうち軽小説」の数 L と「確認済み小説のうち非軽小説」の数 N を集計し、N−L が閾値以上なら非軽小説、L−N が閾値以上なら軽小説と推定する。閾値は作業設定に保存して実行ごとに明記する。未指定なら差20冊を使い、ユーザーが変更した場合は新しい値で再計算する。

- 単書媒体が小説と確認できた、証拠付きの直接判定だけを種にする。漫画・画集・実用書・音声・脚本・媒体未確認はLにもNにも加算しない。画像主体の小説は漫画とは限らず、本文・構成・同版書誌で判別する。同じ書籍・巻の複製や形式違いを重複加算せず、合本は1冊として収録単巻と二重加算しない。連帯推定・未判定・文庫範囲外だけの判定は種に数えない。
- 実書または照合済み書誌の著者・出版社を使う。原作者・作画者・絵師・翻訳者の役割を区別し、同姓同名や別名は対応が確認できた場合だけ統合する。著者不明・出版社不明を一つの実体として集計しない。母出版社へ文庫を拡張する規則ではない。
- 直接判定は連帯推定より優先する。著者・出版社または共著者の結論が衝突した本は判定待ちとし、直接確認へ戻す。軽小説と推定しても文庫範囲・巻版・完全性の確認は続ける。
- 非軽小説の連帯判定で除外した本は、通常の直接判定による対象外と分けて保管する。既存の原因フォルダを優先し、その配下を「著者連帯」「出版社連帯」「著者・出版社両方の連帯」に分ける。両方の根拠は一方へ丸めない。原本を移動して保持し、削除しない。
- 各結果に判定方法、対象実体、著者／出版社、L・N・差・閾値、種の参照、元と現在のpathを記録する。種の訂正で結論が変わった場合は追記で再判定し、以前の連帯保管本も追跡できるようにする。旧方式で漫画等を票にした結果は無効化して再計算し、単書媒体が不明な連帯除外本は媒体確認待ちへ戻す。単書で確認済みの漫画等の分類は保持する。

集計は `uv run scripts/association.py 判定種.jsonl 候補.jsonl --threshold 20` で確認できる。これは判定JSONLを標準出力に出し、書籍の移動や台帳更新は行わない。入力行は `book_key`（同書同巻の重複排除キー）、`authors`、`publishers` と、単書媒体 `media_kind: novel / comic / other / unknown`、その根拠 `media_evidence` を持つ。媒体欄・根拠のない旧行は自動的に小説扱いせず確認待ちにする。種にはさらに `method: direct`、`verdict: ln / non_ln`、`evidence`（直接判定の根拠）を付ける。本機の種・設定・結果は作業データの `association-evidence.jsonl`、`association-policy.json`、`association-decisions.jsonl` に保存する。続行時はこの設定と直接判定種を読み、新しい直接判定を反映して再集計する。各実行の種と集計のスナップショットも残し、`seed_group` の主体別参照から当時の判定種へ戻れるようにする。

## 棚と名前

```text
棚/
  電撃文庫/
    [著者][絵師][発売日] 作品の題名 2.epub
    [著者][絵師][発売日] 作品の題名 2 特典 書き下ろしSS.epub
  MF文庫J/
    [著者][絵師] 別の作品 新装版.epub
  _レーベル未同定/
    [著者] 文庫が未確定の本.epub
```

- 各巻の具体文庫名をフォルダに使う。同じ作品でも版の文庫が異なれば別フォルダ。
- ファイル名は `[著者][絵師][発売日] 題名.拡張子`。文庫は名前に重ねない。
- 未確認のタグは省略。著者不明なら絵師も出さず、日付を推測で埋めない。
- 状態別の階層・作品別フォルダは作らない。連載状況の調査は入架の条件にしない。
- 欠巻TXTを作らない。既存TXTの削除は、内容が欠巻標と確認できたものを対象にする。
- 文庫未同定フォルダは未調査本の一時的な受け皿。調べても確定しない本は、下記の理由別保管へ移す。

名前はNFKC、Windows禁止文字の全角置換、空白整理の順で正規化する。長音符と巻を区別する記号は保つ。副題・上下・分冊・合本・特装・電子限定・新装版は版の識別情報として残す。OPFの末尾に付いた既知の文庫名だけを除き、題名中の括弧を一括削除しない。

## 保存と記録

- 台帳は追記式。訂正も同じ巻IDで追記し、履歴を残す。
- 整理では移動・改名を使い、比較対象と修復前原本を保管する。削除はユーザーが指定した範囲と条件に限る。
- `apply` は元ファイル、書誌タグの維持、計画と現在の台帳の一致を確認する。文庫タグを文庫フォルダへ移す移行では、台帳と移動先を照合する。
- 旧配置規則の計画は作り直す。書誌が不明なら空欄か未決にし、処理済みの批次は再実行しない。

## 対象文庫

ユーザーの指定範囲を維持する。現在の範囲表は作業データの `scope-policy.json` に保管する。出版線の追加や変更が必要なときだけ根拠を更新する。

1. 主サイトの側欄に具体名がある文庫・出版線を整理対象にする。明記された休刊・廃刊も含む。
2. 歴史表や旧記録だけにある文庫は、範囲確認待ちとして保管する。
3. 範囲外と確認できた出版線は、対象外に分類する。

母出版社や集約ページ名は具体文庫の証拠ではない。未識別を範囲外にしない。BL等の内容分類も、具体的な書誌・販売分類・本文の証拠で決める。

## 進め方

スキルのディレクトリを基準に、次の順で進める。

1. `uv run scripts/cli.py status` で棚・置き場・作業データの設定を確認する。
2. `uv run scripts/cli.py materials --count 20` で材料を集める。件数はユーザーの指定と実読できる量に合わせる。未決も再調査する場合は `--include-pending`。
3. 単書の媒体種別を確認し、小説に限って軽小説判別へ進む。対象となる本は実際の内題・柱・巻別・奥付を読んで候補と突き合わせる。候補の順位や部分一致は同定根拠にしない。
4. 確定した巻は `record`。調査後も配置できない本は理由別保管へ移して `pend`。既持同巻なら採用前に版の比較を行う。
5. `audit` で重複配置先・ISBN・指紋・書誌矛盾・実体の欠落を確認する。
6. `plan` の移動先と件数を読み、`apply` する。取消控え、現物、追記されたpathを確認して終える。

```bash
uv run scripts/cli.py record --path "入力.epub" --title "作品の題名 2" --label "電撃文庫" --author "著者" --artist "絵師" --date "240809" --why "実奥付と同巻書誌を確認"
uv run scripts/cli.py pend --fp "指紋" --path "未確定.epub" --reason-dir "置き場/版別の照合待ち" --why "原版と再版を区別する奥付が不足"
uv run scripts/cli.py audit
uv run scripts/cli.py plan
uv run scripts/cli.py apply "計画.jsonl"
uv run scripts/cli.py undo "取消.jsonl"
```

計画は棚全体の既存採用本も対象にする。既存棚の再配置では件数と対象を確認し、今回の依頼範囲を超える移動を実行しない。

## 調査後も配置できない本

1. この手順は整理未決・種類判別待ちの本に適用する。非ライトノベルと判断した本は上記の中止規則に従う。移す前に、置き場の既存理由フォルダを調べる。名前だけでなく用途を読み、今回の障害に合うものを再利用する。同義のフォルダを増やさず、該当先が無い場合だけ作る。
2. 理由は「未処理」ではなく、次に必要な作業が分かる粒度にする。例：対応する親巻が未確認、原版と再版の区別待ち、収録先未確認、文庫を持たない特典の保管先確認。実際の障害と対象範囲外を区別する。
3. `pend` に実体・理由フォルダ・根拠を渡し、移動、未決の現path、既存巻の棚外保留を一緒に記録する。元データを保持し、移動先の衝突、指紋、台帳の鮮度を確認する。移動失敗時は成功扱いにしない。
4. 本機の実行記録に試した資料、不足証拠、再開条件を残す。保留は採用取消や削除を意味しない。通常の配架計画で棚へ引き戻さず、補証後は `record --id ... --on-shelf` で明示して再開する。

既に理由フォルダ内にある本も、理由が変わった場合だけ移す。今回触っていない未調査本や完了済み批次まで一括移動しない。終了時には今回空いたディレクトリを確認して片付け、棚・置き場のルートは残す。

## 書誌の確認

| 項目 | 主に見るもの | 注意 |
|---|---|---|
| 題名・巻・版 | 実内題、柱、奥付 | 柱も誤るため、矛盾時は兄弟巻と比較する |
| 文庫・著者・絵師・紙日付・ISBN | 手元のラノベの杜索引と実奥付 | 作者・原作・挿絵・デザインの役割を分ける |
| 電子版の表示・特典・分冊 | 実書と出版社・BookWalkerの同版ページ | 通常版へ黙って統合しない |
| 任意の作品ID・収録関係 | RanobeDB、実目次 | DB順序は表紙の巻番号とは限らない |

手元の索引から探し、足りないときに杜、出版社、RanobeDB、BookWalkerを調べる。`materials --deep` は追加の外部材料が必要なときに使う。

紙の初版・実際の発売日、電子配信・制作日、重刷日を区別する。杜の候補は同巻・著者・具体文庫と初刊月を確認して採る。ISBN一致でも特殊電子版への流用は避ける。`YYMM00` は月精度で、00日は未知。未知項目は後日の補証対象として残す。

著者名は空白で分割しない。OPFの複数creatorが共同著者とは限らない。索引に無いこと、短いこと、画像が多いことだけで非小説や欠損と決めない。

### 番外・特典から親をたどる

単独の番外・特典の題名で情報が見つからないときは、対応するシリーズへ検索を広げ、巻が分かる場合はその巻の限定版・店舗購入特典・円盤特典・配布告知を調べる。手元の台帳と本篇奥付、出版社のシリーズ一覧・巻別ページを入口にする。

シリーズとの関係と特定巻への対応は別々に確認する。検索候補、同じ登場人物、共通著者だけで対応巻や版を決めない。複数文庫・新装版・漫画版があるシリーズは、実際に対応する版まで照合する。確認できた関係と文庫で配架し、番外・特典の題名と版の違いを維持する。親巻のISBN・発売日・画師は、当該資料にも当てはまる証拠がある項目だけ使う。

親を調べても特定できない場合や、実体が独立文庫版ではない場合は、その違いを根拠とともに記録して理由別に保管する。

## 種類と比較

種類は `本篇 / 特典 / 番外 / 短編集 / 合本版 / 其他`。単独特典には対応巻の題名を付ける。`電子特典付き` は特典を含む本篇。合本は収録単巻を数えて新規巻を増やさず、1容器・1条目として扱う。

同巻候補はISBN、実巻別、題名・著者・版を確認する。`dup` と `oya` は候補の確認に使う。結果は証拠と照合し、確定した情報だけ `record` に渡す。サイズや形式は保管版選択の参考であり、内容一致や品質優越の証明ではない。

比較は全spineの有序本文とruby、全画像、描画SVG、埋込フォント、資源参照を対象にする。同じ文字数でも同じ正文とは限らない。差異や固有資料が残る版は別保管する。画像の縮小類似度だけで固有画像の不存在を断定しない。

修復は根拠のある参照補正に限定し、原本を残す。修復前後の正文・ruby・画像・未変更メンバーを比較し、修復読本を検証する。存在しない画像やCSSを復元したことにしない。注意点の詳細は [記録/1-壊れ方.md](記録/1-壊れ方.md) を参照する。

## 設定・補助命令

場所は環境変数、スキル直下の `.env` の順に読む。`RANOBE_SHELF`、`RANOBE_INBOX`、`RANOBE_VAR`、`RANOBE_CACHE` を使う。`RANOBE_CACHE`（既定はスキル直下の `cache/`）は杜の索引と問い合わせの控えで、作り直せる。絶対パスは設定・台帳・実行結果にだけ記録し、手順や例に固定しない。

- `config --shelf "棚" --inbox "置き場" --var "作業データ"`：場所を設定する。`config --default` は提示された提案を使う場合のみ。
- `record --id "巻ID"`：既存巻を訂正。`--fp` は材料の指紋、`--isbn` は確認済みISBN。
- `record --kind "種類" --work "作品ID" --num 2`：確認できた関係だけ記録。作品IDと順序は任意。
- `record --off-shelf "理由"`：棚外保管の判断。`--on-shelf`：補証済みの棚外保留を解除。`--retire-into "統合先ID"`：重複行を統合。原本を現位置に保つときは `--leave`、誤対応した実体を切るときは `--only`。
- `pend --reason-dir "理由フォルダ"`：置き場内の理由別保管先へ移動して未決を記録。既存の理由フォルダを優先する。
- `record --noted`：指摘を読んだうえでの決定を記録。`--by user` はユーザーが答えを指定した場合に使う。
- `work "作品ID" --name "表示名" --why "根拠"`：任意の作品関係を記録する。
- `ask "検索語"`：追加書誌を調べる。`mori.py find "題名"`、`mori.py update`：索引の検索・差分更新。`mori.py crawl` は索引全量の再取得が必要な場合だけ使う。

`var/` の台帳・保管原本・取消控えは作業資産であり、説明の掃除と一緒に消さない。検証方法は [記録/2-実測.md](記録/2-実測.md) を参照する。

## 共有する知識と本機の記録

共有するスキルには再利用できる処理規則、判断基準、検証方法を残す。作品固有でも、版による巻の分割違いや特典対応など今後の取り違えを防ぐ注意点は、根拠を添えて [記録/1-壊れ方.md](記録/1-壊れ方.md) に集約する。

この機械のパス、処理件数、批次、蔵書ID、SHA一覧、移動・検証の成否、次の作業は `記録/local-run.md` と設定された作業データへ記録する。`local-run.md` は `.gitignore` の対象。継続作業では存在すれば読み、無ければ共有規則と現在の設定から始める。台帳と取消控えを一次記録にし、作品・巻・管理ID・容器・画像枚数を区別して報告する。

道具や手順を変更したら、仮の棚で `uv run scripts/test.py` と `uv run scripts/check.py` を通す。
