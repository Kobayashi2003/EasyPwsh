# ranobe-shelf

**判断はあなたがする。道具は確定したことしかしない。**

道具は測って、記録して、決まったとおりに動かす。
どの本かを決めるのはあなた。道具にその判断は一つも入っていない。

    python scripts/cli.py <命令>

---

## 破ってはいけないこと

**この五つは、事情がどうあれ曲げない。** 残りは全部この下に立つ。

| | |
|---|---|
| **消さない** | 操作は移動と改名の二つだけ。退けるものは隔離先へ**移し**、理由を残す |
| **台帳は追記のみ** | 間違えたら新しい行を足して上書きする。古い行は消さない |
| **三つの門を通す** | `apply` は ①元があるか ②タグが減らないか ③台帳が今のものか を通る。`--force` で外せるのは③だけ |
| **決められないなら決めない** | 取りこぼしは後から拾えるが、まぎれ込みは拾えない |
| **測っていない数は書かない** | 率も割合も、`記録/2-実測.md` に無いものは書かない |

## 棚の形

    棚 / 1. 連載中 / [レーベル][著者][絵師][発売日] 巻の題名.epub
       / 2. 打ち切り / …
       / 3. 完結    / …
       / 4. 未分類  / …
       / _其他      / …

**二段しかない。作品ごとのフォルダは作らない。**

だから **系列名を決めなくてよい** — 何と呼ぶか、どこまでが同じ作品か、
派生をどう扱うか、という判断が丸ごと要らない。
その代わり **四つのタグを一冊ずつ確かめる**のが仕事になる。

    [レーベル]  [著者]  [絵師]  [発売日]

★ **二番目の括弧は必ず著者。** 著者が取れないときは絵師も出さない
（`[レーベル][イラスト]` と `[レーベル][著者]` が見分けられなくなるため）。

タグが揃わなくても棚には置ける。後で分かったら付け直せばよい
（門②が「タグが減る付け直し」を止めるので、情報は落ちない）。

### 名前の揃え方

```
① NFKC で全角を半角へ揃える     ２→2  Ａ→A  ！→!  （→(  ｶﾞ→ガ
② Windows が拒む 9 字だけ全角へ  \ / : * ? " < > |  →  ＼／：＊？”＜＞｜
③ 制御文字を落とし、空白を詰め、末尾の点と空白を削る
```

**順序が大事。** 先に揃えないと `？` と `?` が混ざり、後で逃がさないと置けない。
結果として `？ ： ／ ＊ ＜ ＞ ｜ ＼ ”` の 9 字だけが全角で揃う。

★ **長音符 `ー` は日本語の字。半角にしない**（`コーヒー` が壊れる）。
波ダッシュ `〜` と `～` は `~` に揃える。

## 一周の流れ

```
（置き場の確認）→ materials  →  判断する  →  record / pend  →  work  →  audit
                              (あなた)                              ↓
                                              plan → 中を見る → apply → undo
```

一度に扱うのは **20〜30 冊**。それ以上は材料を読み切れず、判断が雑になる。

### 零 置き場を確かめる（初回だけ）

置き場は**三つ**。決まり方は `環境変数 → .env → 訊く` の順。

| | | 既定 |
|---|---|---|
| 棚 | `RANOBE_SHELF` | 整理済みの蔵書 |
| 置き場 | `RANOBE_INBOX` | まだ整理していない実体 |
| 作業 | `RANOBE_VAR` | 台帳・索引・控え・計画・取消・隔離。**唯一の資産**。既定はスキルの直下 `var/`（`.gitignore` で版から外してある — 索引だけで 23 MB あるため） |

```
python scripts/cli.py status
```

未設定なら、これまで使っていた場所が表示される。
**人に見せて確かめてから**どちらかを実行する。

```
python scripts/cli.py config --default
python scripts/cli.py config --shelf "…" --inbox "…" --var "…"
```

書く先は **スキル直下の `.env`**（注釈つき。直に開いて直してもよい）。

★ `.env` を `作業` の中に置くことはできない。**var 自身がそこに書いてある**ので、
先に読めないと場所が分からない。

## 判断の原則 — 全部の判断に効く

### 確定と不確定

**確定** = その情報だけで 100% 決まる。**不確定** = 決まらない。可能性が増えるだけ。

コードは確定した手順で確定したことだけを扱う。
不確定なものを詰めるのがあなたの仕事で、**詰め切れないなら詰めない**。

### 示唆であって、断定ではない

ファイル名に `特典` とあれば、それが特典である**可能性が増える**。
特典だと決まったわけではない。

    ✗ 「特典」と書いてあるから特典
    ○ 「特典」とある／字数が 20,000 字に遠く届かない／杜にも RDB にも無い → 特典

    ✗ 『ゲーマーズ』と一致したから特典（書店名でもある）
    ○ 137,489 字ある。書店名の可能性が高い → 特典としない

**杜の索引の「示唆」も同じ。** 部分一致で出たものは候補であって答えではない。
奥付のレーベルと発売月が合っているかを見てから採ること。

### 可信度と参考有効範囲

| 材料 | 可信度 | 参考有効範囲 |
|---|---|---|
| ISBN | **確定** | どの本か。一致すればそれだけで決まる |
| **本文の柱** | **高** | **その本が自分を何と呼んでいるか**（下記） |
| 杜の一行（題名が完全一致） | 高 | レーベル・著者・絵師・発売日 |
| 奥付のレーベル | 高 | レーベル（実測 44% で取れる） |
| 奥付の紙の発売日（初版付き） | 高 | 発売日。**月までしか比べない** |
| RDB の巻一覧 | 高 | 巻の並び・完結 |
| 同じ批次の他のファイル | 高 | **どの源も知らない本を束ねる**（下記） |
| OPF の題名 | 中 | 名乗っている題名 |
| 本文の字数・画像・頁 | 中 | 種類（本篇／特典／漫画） |
| 杜の索引の部分一致 | 低 | **示唆のみ** |
| ファイル名 | 低 | 手がかり。**根拠にしない** |
| OPF の `dc:publisher` | 低 | 出版社。**レーベルではない**（実測 261 件で一致 0） |

**参考有効範囲は目安であって、制限ではない。**
範囲の外の問いに効くと思えば使ってよい — 「なぜ効くのか」を `--why` に書くこと。

### ★ 中身が名乗る題名を見る — 柱 ＞ 奥付 ＞ OPF ＞ ファイル名

ファイル名は**一冊ずれていることがある**。手元に無い巻の分だけ前へずれる。

```
ファイル名 魔術師の杖①        中身 魔術師の杖 短編集①
ファイル名 短編集①            中身 魔術師の杖⑧
ファイル名 パラディンⅢ〈上〉    中身 パラディンⅢ〈下〉
```

`materials` は本文の頁の頭に出る書名（**柱**）を拾って調査記録に残す。
柱は本文と一緒に組まれるので、四つの中では一番ずれにくい。

★★ **日付の幅が止めたものを、名前の側で通してはいけない。**
幅が言っているのは「名前と源が食い違っている」ことだけで、
**どちらが正しいかは言っていない**。ここを名前に倒して**九件を取り違えた**
（壊れ方 1-9）。止まったら中身を読む。

★ 柱も間違えることがある（実測-35）。出版社が二巻の柱に一巻の副題を
入れたまま出していた例がある。**柱が食い違ったら、手元に兄弟巻が在るかを見る** —
二冊とも在って日付も題名も源と揃うなら、柱の方が誤っている。

★★ **柱の突き合わせを道具にやらせない。** 一度そういう門を書いて捨てた。
柱は本文へ地続きに続き、副題を省き、80 字で切れるので、
「題名で始まっているか」を機械が判じられない。実際に測ったら
**取り違えの本当の一件を『確かめられない』と読み、合っている本を『食い違う』と
読んだ**。両方向に外す門は、無いより悪い — 正しいものを人へ回しながら、
間違ったものを通してしまう。

見つけ方として当てになるのは、**奥付が印刷した発売日**との突き合わせ
（`audit`。1,248 巻で誤検出 0、取り違え 8 件を発見）。
柱は `materials` が並べるので、**人が読んで**使う。

### 手元のファイルどうしも証拠になる

源はライトノベルしか知らない。**源が答えないことは「実在しない」ではない。**
同じ批次に**著者が同じで題名の幹が同じファイルが複数ある**なら、それは同じ作品。

    10 俺の妹が最高のオカズだった ～射精禁止の修学旅行と…～
    06 俺の妹が最高のオカズだった ～妹はお兄ちゃんが射精…～   ← 著者も幹も同じ
    09 俺の妹が最高のオカズだった ～いちゃラブしても真顔…～

実測でここを落とした。三源とも答えなかったので三冊とも `其他` に落ち、
**蔵書から静かに消えるところだった。**

### 一致・矛盾・不明

- **不明は一致に昇格しない。** 否定する材料が無いのは、肯定ではない
- **数で矛盾を押し切らない。** 三つ一致・一つ矛盾は「矛盾あり」
- **一致した材料だけを台帳に書く。** 矛盾したもの・不明のものは書かない

### ★ 何が食い違ったら止まるのか

| 食い違ったら | |
|---|---|
| **著者・体裁・巻号** | **止まる。** 別の本の疑い |
| 題名・レーベル・発売日 | **止まらない。** 裏付けにしか使わない |

五項目すべてで止めていたとき **2,488 件が誤検出**だった。
巻号を足したら本当の取り違え **87 件**が出てきた。

- **発売日は月までしか比べない。** 奥付は電子版の配信日、DB は紙の発売日。
  **月まで見ても 24% はずれる**（両方ある 461 冊）
- **著者は `× & ・ , 、 / ;` で割る。空白では割らない。**
  `逆井　卓馬` が別人二人になる。`、` の抜けで未決の **48%** が止まっていた

## 判断 一 この一冊は何か — 源の使い分け

| | 何の権威か | 答えられないこと |
|---|---|---|
| **ラノベの杜** | **一冊の書誌** — レーベル・著者・絵師・ISBN・紙の発売日 | 系列という概念が無い（平らな月刊リスト） |
| **RanobeDB** | **作品の構造** — 巻の並び・book_type・完結・ISBN 逆引き | レーベルが弱い。反映が遅い。題名が英語で返る（43%） |
| **BookWalker** | **売り場の現実** — 出版社が付けた名前・完結/特典/分冊版のタグ | 著者が載らない。取り下げがある |

**合わせない。** 項目ごとに一次の源を決め、他は検め（前節「一致・矛盾・不明」）に使う。

| 欲しいもの | 一次 | 検め |
|---|---|---|
| レーベル・著者・絵師・ISBN・紙の発売日 | 杜 | 奥付・OPF |
| 電子の配信日 | RDB `releases[format=digital]` | 奥付 |
| 巻の並び・本篇か派生か | RDB `sort_order` / `book_type` | 題名の数字 |
| 完結 | RDB `c_end_date` / BW `comp` タグ | 互いに |

### 引く順序

```
① 手元の 杜 索引         零網。ここで大半が揃う
② 無ければ 杜 を検索      3.5 秒。結果は索引に書き戻す
③ それでも無ければ RDB/BW  最後の手段（--deep）
```

杜 の検索は **月×レーベルの表ごと**当たるので、一度に百行返ることがある。
自分の探している題名を**自分で選り分ける**こと。

★ **杜の題名をそのまま棚に出さない。** デビュー巻には受賞の但し書きが付く
（索引 90,995 件中 **1,172 件**）。`mori.title_of()` が落とす。

    ムーンスペル!![第16回ファンタジア長編小説大賞＜佳作＞]  →  ムーンスペル!!

### 題名が当たらないとき — レーベル×発売月で候補を小さくする

奥付から レーベル と 紙の発売日 が両方取れたら（実測 26%）、
`materials` はその月のそのレーベルの一覧（十数件）を並べる。

**これは判断ではない。** どちらも奥付に書いてある事実なので、候補の集合は
確定している。その中から選ぶのはあなた。字数・巻号・著者と突き合わせること。

### ISBN が読めたら、それで決まる

    epub の奥付の ISBN  →  杜の索引で一致  →  レーベル・著者・絵師・日付が確定
                        →  RDB /releases?q=<isbn> → 作品 id と並び順が確定

**ISBN 一致は唯一の確定。**他の材料は要らない。
ただし手元で読めるのは **10%**（実測 50 冊）。

★ **RDB の `sort_order` は背に印刷された巻号ではない。**
`.5` の巻も一つと数えるので、`六畳間の侵略者!?8` は `順9` になる。
台帳の `巻号` にはこの**並び順**が入っている — 欠けを数えるにはこちらが正しく、
背の番号として読むと間違える。棚の名前は題名が持っているので支障は無い。

## 判断 二 種類は何か

`本篇 / 特典 / 番外 / 短編集 / 合本版 / 其他`。小説でないものは全部 `其他`。

**`其他` は片道。** 棚から外れるので、間違えると蔵書から静かに消える。
源が答えないだけで `其他` にしない。

杜の索引の**レーベルそのものが手がかり**になる — `ヤングガンガンコミックス`
`角川コミックス・エース` のような漫画レーベルなら `其他`。

### 特典は形ではなく出どころで決まる

`『対応巻』` を冠しているものは、**中身を見る前に特典**。

    『これはゾンビですか？10 …』購入特典   0 字 / 画像 56 枚 / 56 頁

形で判ると `其他` に落ち、「どの巻の特典か」という唯一の情報が消える。
ただし `『』` の中身が画集・ガイド・コミカライズなら小説の特典ではない。

**平らな棚では特典は迷子になりやすい。** 奥付も ISBN も無く、杜にも載らない
（出版物ではないため）。だから**二つとも**やる。

```
タグは対応する巻から継ぐ         レーベル・著者・絵師・発売日
題名は対応する巻の題名で始める     … 特典 <特典名>
```

    [GA文庫][小林湖底][りいちゅ][251213] うっかりドロボウに…天職でした.epub
    [GA文庫][小林湖底][りいちゅ][251213] うっかりドロボウに…天職でした 特典 書き下ろしSS.epub
                                                            ↑ 母巻のすぐ下に並ぶ

★ **『1』だけでは足りない。** 旧い棚では作品フォルダの中に居たので
それで済んだが、平らな棚では**どの作品の特典か分からなくなる**
（同じ著者が二つの作品を持っていれば、タグも同じになる）。

**対応巻の探し方 — 数を手で書かない。**

```
① OPF の 『…』 の中身を、そのまま杜の索引に問う
② 当たった行の発売日が、ファイル名の日付タグと合うか見る（実測-30 で +0 日）
③ 『』が杜の題名の**頭だけ**（副題が無い）なら、日付で絞る —
   同じ日に出た本のうちその『』で始まるものが一つだけなら、それ
```

★★ **対応巻の ISBN を人が書かない。** 一度書いて、それが実在する別の本の
ISBN だったので道具は正しく引いてしまい、**八件が無関係の作品に付いた**。
確かめは `audit` の「特典の頭が、その本の OPF の『』と食い違う」が持っている。

★ 作品 id は**台帳の対応巻から継ぐ**。RanobeDB を副題込みの長い題名で
検索し直すと当たらず、作品なしのまま 4. 未分類 に落ちる（実測-31）。
題名は `{対応巻の題名} 特典 {名}` と組んであるので、` 特典 ` の手前で引ける。

### `【電子特典付き】` は特典ではない

**特典が付いている本篇の巻**であって、特典そのものではない。
逆にファイル名に何も無くても OPF に `購入特典SS` とあればそれは特典。

### 中身の実測値

    本文 20,000 字未満     本篇の一冊ではない
                         5,000〜60,000 の間には 2,862 冊中 16 冊しか居ない

    漫画とみなすのは二つ揃ったとき
      ① 20,000 字未満   ② 画像 ÷ 頁 ≥ 0.9 かつ 頁 ≥ 10

**片方だけで決めない。三通りとも実測で否定されている。**

    画像の数だけ  「20 枚以上」でラノベの 3 割を取り違えた
    字数だけ     漫画の 7,092 字 ＞ 特典の 834 字（重なっている）
    比だけ       比 0.5 以上が 2,862 冊中 2,462 冊

**合本版は名前では見分けられない。** `…22.epub` が 2,716,416 字あった。

### 題名は二か所を見る

ファイル名と OPF の題名の**両方**にかける。
ファイル名は本篇同然なのに OPF にだけ画集と書いてあった件が二つある。

## 判断 三 どの作品で、状態は — 棚の一段目

**保存しない。時間の関数なので毎回計算する。**

```
3. 完結     源が完結と言っている（RDB c_end_date が 99999999 でない／BW の comp）
2. 打ち切り  未完結 かつ **最終巻から 12 か月を過ぎた**
1. 連載中    未完結 かつ 最終巻が 12 か月以内
4. 未分類    最終巻が分からない
```

道具に渡すのは `完結` と `最終巻` の二つだけ。状態はそこから計算される。

```
python scripts/cli.py work rdb:6547 --last 20250910 --done false \
  --name "86―エイティシックス―" --why "RDB の c_end_date は 99999999"
```

★ 最終巻は**既に出た**巻の最新。予告の巻を入れない。
★ 86 は最終巻から 11 か月。**あと一月で打ち切りに変わる** — だから保存しない。

### 作品 id は付ける。名前は付けない

`--work rdb:6547` を付けると、同じ作品の巻が違う状態に散らばらなくなる。
**名前は付けない。** `--name` は報告に出すためだけで、照合には決して使わない。

作品 id が無い巻は `4. 未分類` に落ちる。それは正しい答えであって、逃げではない。

## 命令

### materials — 材料を出す

```
python scripts/cli.py materials --count 20
python scripts/cli.py materials --count 20 --deep     # RDB/BW にも問う
```

台帳に着いている実体と未決は飛ばす。
**材料は全部 `var/survey/<指紋>.json` に残る** — 画面に出るのは要約。
判断に迷ったらそのファイルを読むこと。

### record — 決まった一巻を書く

```
python scripts/cli.py record --fp <指紋> --path "…" \
  --title "86―エイティシックス―Ep.9 ―ヴァルキリィ・ハズ・ランデッド―" \
  --label 電撃文庫 --author 安里アサト --artist しらび --date 210210 \
  --isbn 9784049136050 --kind 本篇 --work rdb:6547 --num 9 \
  --why "奥付の ISBN が杜の一行と一致。RDB の 9 巻とも発売日が合う"
```

- `--why` は必須。**空にできない**
- `--by user` は人が答えを告げたときだけ
- `--noted` は**見た上でこうしている**とき。`audit` の指摘（タグの欠け・
  作品なし・特典の頭の食い違い）が下がる。源の方が誤っている、絵師が居ない
  一般小説、どちらの源も持っていない児童書 — どれも直しようが無い。
  毎周同じ指摘が出ると本当の指摘がその中に埋もれるので付ける
  （壊れ方 8-4）。**分からないものを黙らせるのに使わない** — それは `pend`。
  一度付けたら `--id` で書き直しても**引き継がれる**（源についての見立てなので、
  その巻を書き直しても有効。引き継がないと、作品を足しただけで指摘が戻る）
- `--off-shelf <なぜ>` は**持ってはいるが棚に並べない**とき。実体は今在る
  場所（置き場）のまま、台帳の行は残る。`plan` はその巻を動かさず、`audit` が
  「棚に置かないと決めた巻」に挙げる。作品が引けず状態が決まらない本、
  合本版、小説でないもの — 棚の段に属さないが**持っていることは消さない**。
  `--noted` と同じく `--id` で書き直しても**引き継がれる**
  （引き継がないと、一欄直しただけで棚へ戻る）
- 判断を改めるときは `--id V000123` で**どの行かを明示する**。
  そのとき既に付いている実体は**引き継がれる**（作り直すと迷子になるため）
- 同じ巻に実体が複数あるときの採用順 — **① epub ② 大きい方 ③ 新しい方**。
  `--id` を付けて別の実体を指すと、今指した方が採用になり、
  残りは `plan` で**隔離へ移る**（消さない。なぜそこに在るかの覚え書きも残る）

- `--only` は、間違って一つの巻に寄せた実体を**切り離す**とき。今指した実体
  だけを残す。**別の本を「同じ巻の二つ目の実体」と読み違えた**ときに要る

★ **同じ巻に二つの巻ID が立ってしまったとき** — 指紋が違えば別の材料として
上がってくるので、一つの巻を二つの批で拾うとこうなる（`V000183` / `V000344`）。
入れる前に **ISBN が既に台帳にあるか**を見て、あれば人へ回すこと。
畳むのは二段階:

```
python scripts/cli.py record --id V000183 --fp <二つ目の指紋> --path "…" …
python scripts/cli.py record --id V000344 --retire-into V000183 --why "…"
```

`--leave` を添えると**実体を動かさない** — 「同じ巻を既に持っているので、
入ってきた方は採らない」とき。置き場に置いたままにして、`pend` にも出しておく
（出さないと次の周でまた材料に上がる）。

`--retire-into` は**行を消さない**。実体を一つも持たない行を足すだけで、
その巻ID は棚にも隔離にも現れなくなる（`plan` は採用実体の無い巻を飛ばす）。
実体を先に移していないと止まる。畳んだ巻は `audit` の
「他の巻へ統合した巻」に出る。

### pend — 決められないものを出す

```
python scripts/cli.py pend --fp <指紋> --why "杜にも RDB にも無く、奥付も読めない"
```

**決められないことは失敗ではない。** 取りこぼしは後から拾えるが、
まぎれ込みは拾えない。**理由は言い分けること** — 「源が知らない」を
「題名が一致しない」で丸めない。

### audit — 歪みを探す

```
python scripts/cli.py audit
python scripts/cli.py audit --verbose
```

- **同じ名前になる二冊** → 平らな棚での唯一の構造的破綻
- **タグが欠けているもの** → 平らな棚での品質指標。
  ★ タグは位置で読む（レーベル・著者・絵師・発売日）。**レーベルが欠けると
  位置がずれて著者が先頭に来る**ので、置く前に埋めるのが望ましい
- **台帳にあるのに実体が無い** → 手で消された・動かされた本。
  ★ 一度置いたあとは `plan` が何も言わない（動かす必要が無いので）。
  **消えた本を見つけられるのはここだけ**
- **同じ ISBN が二つの巻に** / **同じ実体が二つの巻に**
- **`其他` に落としたもの** → 片道なので必ず目を通す
- **作品を持たない巻** → 状態が `4. 未分類` に落ちている
- **置き場に残っている、既に台帳にある中身の写し** →
  中身が同じ写しは指紋で弾かれるので `materials` に二度と出てこない。
  放っておくと**置き場が空にならず、理由もどこにも出ない**

**批次を終えるたびに走らせる。** 積むほど直しにくくなる。

### plan / apply / undo

```
python scripts/cli.py plan
python scripts/cli.py apply
python scripts/cli.py undo
```

**`plan` の中を見てから `apply`。** 件数だけ見て流さない。
一つでも門に引っかかれば**一件も動かない**。

| | 何を見るか | 引っかかったら |
|---|---|---|
| ① | 元があるか、先が塞がっていないか | 名前がぶつかっている。片方を直す |
| ② | 日付以外のタグの**数**が減らないか／日付が消えないか | 台帳のタグが埋まっていない |
| ③ | その計画が今の台帳から作られたか | **`plan` を作り直す** |

`--force` は門③だけを外す。**門①②は外せない。**

★ 門② が見るのは**数**であって値ではない。**値が入れ替わるのは通す** —
日付は旧い流れと源の紙の発売日で違って当たり前だし、レーベルは
`B6判` から `KADOKAWA` へ直る（実測-26）し、同じ人を源によって
「古河 樹」「古河樹」と書き分ける（実測-25）。値で止めると正しい付け直しが
軒並み止まる。**入れ替わった分は `apply` が知らせる**ので、そこで見る。

だが**消えるのは止める**。だから発売日がどうしても決まらないときは、
**元のファイル名に付いていた日付をそのまま持っていく**こと。落とすと置けなくなる。

★ 値の取り違えは門②では捕まらない。それは `audit` の仕事
（`魔女と傭兵6上` が下巻の ISBN を掴んだのを捕まえたのも audit）。

`apply` は動かしたあと、**空になったフォルダを畳む**（ファイルは一つも消さない）。
棚の一段目と置き場そのものは残す。

★ **塞いでいる相手は先に退かす。** 同じ巻の写しを入れ替えるとき、新しい方の
行き先を古い方が塞いでいる。`apply` は順番を並べ替えてから動かす。
入れ替えが堂々巡りになるときは**一件も動かさずに報告する**
（旧い道具はここで両方を退避させ、その巻が棚から消えた）。

### dup — 既に棚に在る巻かどうか

```
python scripts/cli.py dup
python scripts/cli.py dup --apply
```

置き場の一冊が既に棚に在る巻なら、規則 7-4（epub 優先 → サイズ）で採否を決める。
**棚を残すときは実体を動かさない** — 置き場に置いたまま未決に出す。

突き合わせるのは **ISBN → 作品と巻号 → 題名の完全一致** の順。
前方一致も編集距離も使わない。三つとも外れたら黙る。

★ 題名で当たる道が要るのは、**棚の古い行が ISBN を持たない**ことがあるから。
  物語シリーズ 24 冊が、ISBN だけを見ていたせいで丸ごと二重に書かれた。

### oya — 特典の親の巻を探す

```
python scripts/cli.py oya
python scripts/cli.py oya --apply
```

特典は「その巻を買った人が貰うもの」なので、**親はたいてい自分が既に持っている**。
杜は特典を載せないので訊かない。台帳を引く。

★ 親を絞るのは **題名 ＋ 表紙に印刷された巻号**。`巻号`（RanobeDB の順）ではない。
  「声優ラジオのウラオモテ #15」は表紙が 15 で巻号が 16 — 巻号で当てると
  特典が一つ前の巻に付く。

### gaps — 欠巻の標を立てる

```
python scripts/cli.py gaps
python scripts/cli.py gaps --apply
```

持っていない巻の場所に、**同じ形の名前の `.txt`** を置く。棚は平らなので、
標は抜けているその場所に並ぶ。開けば何の巻かが書いてある。

| | どうするか |
|---|---|
| 何を欠巻とするか | 作品の巻一覧（RanobeDB）のうち、**既に出ていて**手元に無い `main` の巻 |
| タグ | **手元の巻から継ぐ。** RanobeDB の publisher は文庫名ではない（実測-5） |
| 要らなくなった標 | 隔離へ**下ろす**（消さない） |

★ **標は記録ではない。** 台帳と源から毎回引き直す派生物で、台帳が変われば
書き直る。**標を読んで何かを決めてはいけない**（壊れ方 5 章）。
だから `record` の材料にも `audit` の入力にもしない。

★ まだ出ていない巻に標を立てない。予告の巻まで数えると、
**買えるはずのない穴**が棚じゅうに空く。

★ RanobeDB は別の作品を一つの作品にまとめていることがある
（`シャンティ` の第2巻が「マフィア」）。その分だけ**立たなくてよい標が立つ**。
標は毎回引き直る紙なので、見つけたら台帳の作品 id の方を直す。

### 杜の索引

```
python scripts/mori.py status          # 索引の状態
python scripts/mori.py update          # feed と今月± の差分だけ
python scripts/mori.py crawl           # 未取得の月を取る
python scripts/mori.py find "題名"      # 索引を引く
python scripts/mori.py find --isbn …   # ISBN で引く
```

**更新規則**（実測で決めた）

```
主路  rss.xml 一回（31KB / 2 秒）。"電撃文庫 - 2026年10月刊" が
      「どの月を取り直すか」を直接教える
守衛  feed は 15 件しか残らない（観測: 2 日で 6 件 ≒ 5 日ぶん）ので、
      feed に何が載っていても **今月-3〜+4 か月は毎回取り直す**
全量  crawl。264 か月 ≒ 20 分。索引がおかしいときだけ
```

★ **杜は HTTP 200 のまま中身の欠けた応答を返すことがある**（754 バイト）。
一度目のくだしで 15 か月がこれに当たり、**索引から 4,709 件が静かに消えた**
（「成功 264 / 失敗 0」と報告しながら）。今は過ぎた月が 0 件なら取り直し、
それでも 0 件なら前の分を残して報告する。**`crawl` の最後の行を必ず読むこと。**

延期は稀（実測 3,590 本中 33 本＝0.9%）だが、遡りは最大 24 か月。
feed が編集を拾う前提は**まだ確かめていない** — 過去月が編集された標本を
一度も見ていないため。拾わなければ全量で直す。

## 人が「それは違う」と言ってきたら

- 答えそのものを告げられたら `record --by user --id <巻ID>`。推し直さない
- **ただし検めは通す。** 告げられた答えが中身と食い違うなら、入れる前に知らせる
- 判り直して**同じ答えに戻った**なら、根拠を並べて押し返す。黙って従わない
- 人の証拠も「もう一つの源」。食い違いは黙って人に合わせず知らせる

### ★ 一件の指摘は、同じ形が何件あるかを測ってから直す

前の道具で 18 件の差し戻しを追ったとき、指摘は 1 件でも同種は
**8 件・15 件・26 件・1192 件**あった。**必ず数えてから直す。**

そして原因の形はほぼ二つに集約される。まずこれを疑うこと。

    甲  二つの別のことを、一つの判定で兼ねている
        「巻号が読めない」と「この作品の巻ではない」
        「DB の並び順」と「巻号」
    乙  同じ規則が二か所に別々に実装され、片方だけ直された

## 規則を変えたくなったら — `記録/`

この文書は「どうするか」だけ。**「なぜそうなのか」は `記録/`。**
普段は読まなくてよい。**規則を変えるときだけ読む。**（番号は読む順）

    記録/1-壊れ方.md              実際に壊れた 39 件。壊れ方の形ごとに八章
                                 **規則を外す前に必ず。同じ形の穴が既に
                                 開いていないか探す**
    記録/2-実測.md                数えた結果 19 件。測った日と標本の数つき
                                 **数を書く前に必ず。ここに無い数は書かない**
    記録/3-欠巻.md                買っていない巻 1,127 件
                                 （これだけは道具ではなく蔵書の話）

規則はどれも机上で決めたものではない。外す前に、それが**どの壊れ方の
後始末なのか**を確かめること。数は**掛け算で作らない**。
